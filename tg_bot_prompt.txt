Напиши Telegram-бота на Python, который будет общаться с локальной нейросетью через LM Studio.

КОНТЕКСТ:

- Бот будет запускаться на хосте Windows, НЕ в этом контейнере.
- На хосте работает LM Studio с OpenAI-совместимым API по адресу http://localhost:1234/v1
- Ты пишешь ТОЛЬКО код и проверяешь синтаксис. НЕ запускай бота.

ТРЕБОВАНИЯ:

Файл: tg_bot.py

Библиотеки:

- python-telegram-bot версии 20+ (async API, ApplicationBuilder)
- httpx для асинхронных HTTP-запросов к LM Studio
- os, logging, asyncio из стандартной библиотеки

Конфигурация через переменные окружения (с разумными значениями по умолчанию):

- TELEGRAM_BOT_TOKEN — токен бота из @BotFather (обязателен, без дефолта)
- LM_STUDIO_URL — по умолчанию "http://localhost:1234/v1"
- LM_STUDIO_MODEL — по умолчанию "gemma4-12b-hauhaucs@q4_k_m"
- SYSTEM_PROMPT — по умолчанию "Ты — полезный ассистент в Telegram. Отвечай кратко и по делу."
- MAX_HISTORY — по умолчанию 20 (сколько последних сообщений помнить, не считая system)

Команды бота:

- /start — приветствие и краткая инструкция
- /reset — очистить историю диалога текущего пользователя
- /help — справка

Обработка обычных текстовых сообщений:

1. Добавить сообщение пользователя в историю этого чата.
2. Отправить всю историю (system + предыдущие + текущее) в LM Studio по пути /chat/completions.
3. Получить ответ, добавить его в историю.
4. Отправить ответ в чат.
5. Если ответ длиннее 4000 символов — разбить на части по 4000 и отправить по частям.

История диалога:

- Хранится в памяти в словаре: dict[int, list[dict]] по chat_id.
- Обрезается до MAX_HISTORY последних сообщений (не считая system).
- При /reset — удаляется полностью для текущего чата.

Обработка ошибок:

- Если LM Studio не отвечает или таймаут (30 секунд) — отправить сообщение: "⚠️ LM Studio недоступна. Проверьте, что сервер запущен на компьютере."
- Ошибки логировать через logging в stdout.
- Не падать при ошибках — продолжать работу.

Режим работы:

- Long polling через Application.run_polling(). НЕ webhook.
- Логирование уровня INFO в stdout.

Структура кода:

- Асинхронные хендлеры (async def).
- Функция отправки запроса в LM Studio — отдельная, с обработкой ошибок.
- Комментарии на русском, кратко.
- В самом низу — блок if **name** == "**main**": с проверкой наличия TELEGRAM_BOT_TOKEN и запуском бота.

ЧТО СДЕЛАТЬ В КОНТЕЙНЕРЕ:

1. Создай файл tg_bot.py с полным кодом.
2. Проверь синтаксис командой: python -m py_compile tg_bot.py
3. Если py_compile прошёл без ошибок — ответь ровно: TASK_COMPLETE
4. НЕ устанавливай python-telegram-bot, НЕ запускай бота — для синтаксической проверки они не нужны.
5. НЕ создавай requirements.txt и другие файлы — только tg_bot.py.

ВАЖНО:

- Код должен быть ПОЛНЫМ и рабочим. Пользователь запустит его сам на Windows.
- Не оставляй TODO, заглушек, многоточий.
- Не используй API python-telegram-bot, удалённых в версии 20 (например, Updater.dispatcher устарел — используй ApplicationBuilder и CommandHandler напрямую).
- Правильный импорт v20+: from telegram.ext import Application, CommandHandler, MessageHandler, filters
- Правильное чтение сообщения: update.message.text
- Правильная отправка: await update.message.reply_text(...)
